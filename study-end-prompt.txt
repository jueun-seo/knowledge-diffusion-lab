■ 규칙
1. 단계는 오늘 실제로 진행한 순서대로. 다음에 이 순서대로 그대로 따라 치면 똑같이 동작해야 해.
2. 단계 제목 끝에는 `terminal`(터미널 명령), `code: 파일경로`(파일에 쓴 코드), `browser`(브라우저 확인) 중 하나를 붙여.
3. 내가 직접 치진 않았지만 따라 치려면 꼭 필요한 단계(설치, import 등)도 넣고, 그 단계에는 "- 보충: 예" 줄을 붙여.
4. 여러 문제를 다뤘으면 "## 문제:" 묶음을 여러 개 만들어.
5. 분야는 개발 환경, Python 기초, Backend, Database, Frontend, AI·LLM, 배포·클라우드 중 하나. 기타는 쓰지 말 것. 로그인·토큰·인증·권한은 Backend, 화면·React·CSS는 Frontend, SQL·테이블·ORM은 Database, AI·LLM은 AI 모델·프롬프트에 관한 것만.
6. 개념 설명은 오늘 다룬 개념마다 하나씩, 3~5문장. 12살도 이해할 수 있게, 첫 문장은 한 줄 정의, 예시 포함. 이미 있는 개념이면 예전과 다른 새 내용으로. 코드는 `백틱`으로 감싸.
6-0. 개념을 잘게 쪼개지 마. 개념 하나는 여러 용어를 아우르는 큰 덩어리(예: OAuth, JWT 인증, React 상태 관리, SQL JOIN). 클라이언트 ID, 클라이언트 시크릿, 리다이렉트 URI처럼 큰 개념에 딸린 용어는 따로 ### 개념으로 만들지 말고, 그 큰 개념 설명 아래에 "- 용어: 한 문장 설명" 줄로 덧붙여. 이미 있는 개념 목록에 아우르는 개념이 있으면 그 이름을 그대로 써.
6-0-0. 오늘 새 용어가 이미 있는 개념의 일부라면(예: 이미 OAuth가 있는데 리다이렉트 URI를 배움) 새 ### 개념을 만들지 말고, "### OAuth" 아래에 "- 리다이렉트 URI: 한 문장" 줄만 써.
6-0-1. 설명을 쓰지 않을 개념은 개념 설명에도, 단계의 "- 개념:" 줄에도 넣지 마. 단계의 "- 개념:"에는 아래 개념 설명에 실제로 쓴 이름만 적어.
6-1. 개념 설명 문장은 "~해요/~돼요" 같은 말투 대신 명사형으로 끝내. 예: "서버 본체를 만드는 줄.", "자동으로 다시 시작됨.", "8000번 사용, --port로 변경 가능."
7-0. "질문 수"는 이 대화에서 내가 너에게 보낸 메시지(프롬프트)를 처음부터 하나씩 직접 세어 숫자만 적어. 질문 형태가 아닌 메시지(코드 붙여넣기, "응", "다음" 등)도 1개로 세고, 이 정리 요청 메시지만 빼. 짐작하지 말고 실제로 센 수를 적어.
7. "내가 한 질문"에는 이 대화에서 내가 보낸 질문을 처음부터 끝까지 하나도 빠짐없이, 보낸 순서대로 한 줄에 하나씩 번호를 붙여 적어. 내가 쓴 말 그대로 적고, 너무 길면 한 줄로 줄여. 질문 수를 세는 데 쓰니 비슷한 질문도 합치지 말고, 이 정리 요청만 빼.
8. 코드는 반드시 ``` 코드블록 안에. 코드블록 하나에는 명령 하나 또는 코드 한 덩어리만.
