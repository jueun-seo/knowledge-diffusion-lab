```
def find_or_create_user(db, provider, provider_id, name):
    user = db.scalar(
        select(User)
        .where(User.provider == provider, User.provider_id == provider_id)
    )
    if user:
        return user

    username = name
    n = 0
    while db.scalar(select(User).where(User.username == username)):
        n += 1
        username = f'{name}{n}'

    user = User(
        username=username,
        password_hash=password_hash.hash(secrets.token_hex(32)),
        provider=provider,
        provider_id=provider_id
    )
    db.add(user)
    db.commit()
    return user
```
- 개념: 함수, 데이터베이스 조회, 반복문
- 메모: 이미 가입된 소셜 회원이면 바로 돌려주고, 없으면 중복 없는 username과 랜덤 암호화 비밀번호를 넣어 새 회원을 저장해.

### 6. 리프레시 토큰 생성 함수 추가 및 `get_current_user`에서 리프레시 토큰 차단 `code: backend/deps.py`
```
def create_refresh_token(user_id: int):
  exp = datetime.now(timezone.utc) + timedelta(days=14)
  return jwt.encode({'sub': str(user_id), 'exp': exp, 'type': 'refresh'}, SECRET_KEY, algorithm=ALGORITHM)
```
- 개념: JWT 및 쿠키 인증, 예외 처리
- 메모: 14일 만료와 `'type': 'refresh'`를 담은 리프레시 토큰을 만들고, `get_current_user`에서는 `payload.get('type') == 'refresh'`일 때 일반 출입증으로 못 쓰게 `401` 예외를 발생시킨다.

### 7. 로그인 시 `HttpOnly` 쿠키에 리프레시 토큰 저장 및 `/api/auth/refresh` 재발급 경로 구현 `code: backend/routers/auth.py`
```
@router.post('/login', response_model=Token)
def login(
  form: Annotated[OAuth2PasswordRequestForm, Depends()],
  db: SessionDep,
  response: Response,
):
  user = db.scalar(select(User).where(User.username == form.username))

  if user is None or not password_hash.verify(form.password, user.password_hash):
    raise HTTPException(status_code=401, detail='아이디 또는 비밀번호가 틀렸습니다.')

  token = create_access_token(user.id)
  response.set_cookie(
    'refresh_token',
    create_refresh_token(user.id),
    httponly=True,
    samesite='lax',
    max_age=60 * 60 * 24 * 14,
    path='/api/auth',
  )

  return {'access_token': token, 'token_type': 'bearer'}


@router.post('/refresh')
def refresh(db: SessionDep, refresh_token: Annotated[str | None, Cookie()] = None):
  if refresh_token is None:
    raise HTTPException(status_code=401, detail='로그인이 필요합니다.')

  try:
    payload = jwt.decode(refresh_token, SECRET_KEY, algorithms=[ALGORITHM])
  except jwt.InvalidTokenError:
    raise HTTPException(status_code=401, detail='토큰이 유효하지 않습니다.')

  user = db.get(User, int(payload['sub']))

  if user is None or payload.get('type') != 'refresh':
    raise HTTPException(status_code=401, detail='다시 로그인 해주세요')

  return {'access_token': create_access_token(user.id), 'token_type': 'bearer'}
```
- 개념: JWT 및 쿠키 인증, 예외 처리, 데이터베이스 조회
- 메모: 로그인 시 자바스크립트가 읽지 못하는 `HttpOnly` 쿠키에 리프레시 토큰을 저장하고, `/api/auth/refresh`에서는 쿠키의 토큰을 해독·검증해 새 `access_token`을 발급한다.

### 16. `jti`(`UUID`) 기반 리프레시 토큰 DB 저장 및 로그아웃 시 DB·쿠키 동시 삭제 `code: backend/routers/auth.py`
```
@router.post('/login', response_model=Token)
def login(
  form: Annotated[OAuth2PasswordRequestForm, Depends()],
  db: SessionDep,
  response: Response,
):
  user = db.scalar(select(User).where(User.username == form.username))

  if user is None or not password_hash.verify(form.password, user.password_hash):
    raise HTTPException(status_code=401, detail='아이디 또는 비밀번호가 틀렸습니다.')

  token = create_access_token(user.id)
  jti = uuid.uuid4().hex
  db.add(RefreshToken(id=jti, user_id=user.id))
  db.commit()

  response.set_cookie(
    'refresh_token',
    create_refresh_token(user.id, jti),
    httponly=True,
    samesite='lax',
    max_age=60 * 60 * 24 * 14,
    path='/api/auth',
  )

  return {'access_token': token, 'token_type': 'bearer'}


@router.post('/logout')
def logout(
  response: Response,
  refresh_token: Annotated[str | None, Cookie()] = None,
  db: SessionDep = ...,
):
  # DB에서도 토큰 삭제
  if refresh_token:
    try:
      payload = jwt.decode(refresh_token, SECRET_KEY, algorithms=[ALGORITHM])
      row = db.get(RefreshToken, payload.get('jti'))
      if row:
        db.delete(row)
        db.commit()
    except jwt.InvalidTokenError:
      pass

  response.delete_cookie('refresh_token', path='/api/auth')
```
- 개념: JWT 및 쿠키 인증, 데이터베이스 조회, 예외 처리
- 메모: 로그인 시 `uuid.uuid4().hex`로 만든 고유 `jti`를 토큰과 DB `refresh_tokens`에 함께 저장하고, 로그아웃 시 쿠키에서 `jti`를 꺼내 DB 행까지 삭제하여 복사된 리프레시 토큰 재사용을 막는다.

### React 상태 관리 `Frontend`
컴포넌트 내부와 앱 전역에서 변하는 값을 `useState`, `useEffect`, `Context`로 관리해 화면과 라우팅을 자동으로 갱신하는 기법. 예를 들어 `AuthProvider`에서 `token`, `user`, `ready` 상태를 관리하면 `RequireLogin`이 준비 여부와 토큰 유무에 따라 화면 대기(`null`), 로그인 이동(`<Navigate/>`), 자식 페이지 출력(`<Outlet/>`)을 자동으로 전환함.
`useEffect`: 의존성 배열(`[]` 또는 `[token]`)의 값이 바뀔 때 사용자 정보 조회나 토큰 재발급 같은 부가 작업을 실행하는 훅.
`RequireLogin`과 `<Outlet/>`: 로그인 상태를 검사하는 보호 라우트 컴포넌트와 인증 통과 시 실제 자식 라우트 화면이 끼워 들어가는 자리.
제어 컴포넌트 폼(`onSubmit`, `e.preventDefault()`): 입력창 값을 `state`와 연결하고 제출 시 기본 새로고침을 막은 뒤 `JSON.stringify`로 백엔드에 전송하는 방식.

### 웹 브라우저 DOM `Frontend`
웹 브라우저가 화면 요소들을 트리 구조로 표현하여 자바스크립트가 접근하고 조종할 수 있게 만든 문서 객체 모델.
HTML: 화면 요소의 뼈대와 기본 구조를 정의하는 문법.
CSS: 화면 요소의 스타일과 디스플레이를 꾸미는 문법.

### 세션 및 미들웨어 `Backend`
요청과 응답이 오가는 길목에서 공통 작업을 처리하는 검문소(`Middleware`)와 여러 단계의 임시 상태를 기억하는 저장소(`Session`). 예를 들어 `SessionMiddleware`에 `secret_key`를 설정해 `OAuth` 로그인 도중 생성되는 임시 상태값을 서명된 쿠키에 안전하게 보관함. `FastAPI` 내부 기반인 `Starlette`의 미들웨어를 그대로 붙여 인증 흐름의 위조를 막아 줌.
미들웨어(Middleware): 라우터 함수가 실행되기 전후에 모든 요청·응답을 가로채 공통 로직을 수행하는 중간 계층.
세션(Session): 화면이 여러 번 이동하는 로그인 과정 동안 임시 데이터를 잃어버리지 않게 유지해 주는 상태 저장 공간.
암호 서명: `itsdangerous`와 비밀키를 이용해 세션 데이터가 중간에 조작되지 않았는지 검증하는 디지털 봉인.

### 세션 및 미들웨어 `Backend`
요청이 라우트 함수에 도달하기 전후에 보안·인증 규칙을 검사하는 중간 검문소 구조. 예를 들어 FastAPI의 `CORSMiddleware`는 다른 포트(`http://localhost:5173`)에서 오는 브라우저의 `OPTIONS` 사전 요청(`Preflight`)을 검사해 허용된 출처·헤더·메서드·쿠키만 통과시킴.
`allow_origins`: 요청을 허용할 프론트엔드 출처 주소를 지정하는 설정.
`allow_headers`: `Authorization`처럼 요청에 포함될 수 있는 헤더 이름을 허락하는 설정.
`allow_credentials`: 크로스 오리진 요청에서 쿠키 등 자격 증명을 주고받도록 `True`로 여는 설정.
`allow_methods`: `POST`, `GET` 등 허용할 HTTP 요청 방식을 지정하는 설정.

### OAuth 2.0 소셜 로그인 `Backend`
사용자가 비밀번호를 우리 사이트에 알려주지 않고도 구글 같은 외부 인증 서버의 허가를 받아 로그인하는 표준 인증 방식. `Authlib`의 `OAuth` 객체에 구글 클라이언트 정보를 등록한 뒤 `/google/login`으로 사용자를 보내고 `/google/callback`에서 프로필을 넘겨받음. 비밀번호 관리 부담을 줄이면서 안전하게 신규 가입과 로그인을 한 번에 처리할 수 있음.
OAuth 클라이언트 등록: `oauth.register(...)`로 구글의 클라이언트 ID, 시크릿, 메타데이터 URL을 백엔드에 등록하는 초기 설정.
스코프(Scope): `{'scope': 'openid email profile'}`처럼 구글 로그인 시 사용자에게 동의를 요청할 정보의 범위.
리디렉션(Redirect): `RedirectResponse` 등을 통해 브라우저를 구글 인증 페이지나 프론트엔드 화면으로 자동 이동시키는 응답.
콜백(Callback): 구글에서 사용자 허가가 끝난 뒤 인가 코드와 결과를 되돌려 받기 위해 미리 지정한 도착 경로.
사용자 정보(userinfo): 구글이 토큰과 함께 전달하는 프로필 딕셔너리로, 고유 식별자 `sub`와 `email` 등을 포함함.

### JWT 및 쿠키 인증 `Backend`
소셜 인증을 마친 사용자에게 우리 서비스 전용 출입증 토큰을 발급하고 브라우저 쿠키에 심어 로그인 상태를 유지하는 방식. 콜백에서 회원을 확보한 뒤 `set_refresh_cookie`를 호출해 `RefreshToken`을 DB에 기록하고 `response.set_cookie(...)`로 응답에 담아 보냄. 이후 프론트엔드가 백엔드와 통신할 때 브라우저가 쿠키를 자동으로 챙겨 보내 인증을 이어 감.
쿠키(Cookie): 서버가 `Set-Cookie`로 내려보내면 브라우저가 보관하다가 같은 도메인 요청 시 자동으로 실어 보내는 작은 저장소.
리프레시 토큰(Refresh Token): `httponly=True` 쿠키에 담아 안전하게 보관하며 로그인 세션을 길게 유지하는 재발급용 토큰.

### JWT 및 쿠키 인증 `Backend`
짧은 유효기간의 액세스 토큰과 긴 유효기간의 리프레시 토큰을 역할별로 나누어 안전하게 로그인 상태를 유지하는 인증 방식. 예를 들어 `access_token`은 리액트 메모리(`useState(null)`)에만 두고 `Authorization: Bearer ...` 헤더로 API 요청마다 사용하며, `refresh_token`은 자바스크립트가 읽지 못하는 `HttpOnly` 쿠키와 DB에 함께 저장해 새로고침 시 새 액세스 토큰을 재발급받는 데 활용함.
액세스 토큰(Access Token): API 요청 시 신분증처럼 헤더에 실어 보내며 유출 피해를 줄이기 위해 만료 시간을 짧게 두고 메모리에만 보관하는 토큰.
리프레시 토큰(Refresh Token): 새 액세스 토큰을 재발급받기 위한 전용 토큰으로 `HttpOnly` 쿠키(`httponly=True`, `samesite='lax'`, `max_age`)에 담아 보호함.
`jti` (`UUID`): `uuid.uuid4().hex`로 생성해 토큰과 DB `refresh_tokens` 테이블에 함께 기록하는 고유 식별자로, 로그아웃 시 해당 행만 골라 즉시 폐기할 수 있게 해 줌.
`credentials: 'include'`: 다른 포트(출처) 간 `fetch` 요청에서 브라우저가 쿠키를 함께 전송하고 응답 쿠키를 저장하도록 허용하는 옵션.

### 서버 주소 및 URL 조립 `Backend`
프론트엔드 코드에서 백엔드 서버의 기본 주소를 한곳에서 불러와 세부 API 경로와 합쳐 요청 주소를 만드는 방식. `api.js`에서 `SERVER_URL`을 `import`한 뒤 `` `${SERVER_URL}/api/auth/google/login` ``처럼 템플릿 리터럴로 주소를 완성함. 로컬 개발 환경과 실제 배포 서버 주소가 달라져도 설정 파일 한 곳만 고치면 되어 편리함.
템플릿 리터럴: 백틱 안에서 `${변수}` 문법을 사용해 문자열과 변수 값을 직관적으로 이어 붙이는 자바스크립트 문법.
